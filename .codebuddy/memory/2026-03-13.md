## blockchain-adapter: EVM 延迟加载 + 按需安装 viem

### 问题

`viem` 在 `package.json` 中标记为 `optional peerDependency`，但代码通过静态 import 硬引用——没有 viem 时整个包（包括 TON）直接崩溃。

### 解决方案（两步）

**Step 1: EVM 动态加载**

- `factory.ts` 将 `EVMProvider` 从静态 import 改为 `await import("./providers/evm/index.js")`
- `index.ts` 移除 `EVMProvider` 的静态 re-export，改为 type-only export + `loadEvmProvider()` 函数
- `initBlockchainFactory()` 改为 async；新增 `initBlockchainFactorySync()` 用于同步场景
- `factory.getEVMProvider()` 改为 async，自动触发 EVM 延迟注册
- TON 功能现在完全独立于 viem

**Step 2: 按需安装机制**

- 新建 `deps.ts`（参考 Matrix 扩展的 `deps.ts` 模式）
- `isViemAvailable()` / `isSolanaAvailable()` / `isSuiAvailable()` — 可选依赖检测
- `ensureViemInstalled()` — 自动通过 `npm install` 安装 viem
- `assertViemAvailable()` — 用户友好的错误信息
- `getChainAvailability()` — 全链状态一览
- `factory.ensureEvmProviders({ autoInstall: true })` — 工厂级自动安装入口

### 更新的消费者

- `agent-wallet`: `handler-base.ts`（async ensureBlockchainFactory）, `handlers.ts`（await getEVMProvider）, `ton-handlers.ts`（async resolveTonProvider）
- `market-core`: `escrow.ts`（async ensureBlockchainFactory + await getEVMProvider）, `escrow-ton.ts`（async ensureBlockchainFactory）

### 新增导出

- `@openclaw/blockchain-adapter/providers/evm` — 按需加载 subpath
- `@openclaw/blockchain-adapter/deps` — 依赖检测 subpath
- `package.json` 添加 `"type": "module"`
