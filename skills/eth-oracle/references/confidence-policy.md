# Confidence Policy

本文件定义 `eth-oracle` 的证据、置信度、未知项与冲突处理规范。

## 1. 证据对象

每个关键结论都应可拆为如下对象：

```json
{
  "claim": "string",
  "tier": 1,
  "source": "string",
  "observed_at": "ISO-8601",
  "freshness": "live|recent|stale",
  "status": "confirmed|contested|provisional|rumor",
  "supports": ["thesis-id"],
  "notes": "string"
}
```

## 2. 来源等级

| Tier | 含义                   | 默认权重 | 示例                                              |
| ---- | ---------------------- | -------- | ------------------------------------------------- |
| 1    | 直接事实 / 官方 / 链上 | 1.0      | SEC, FED, BIS, 链上数据, 官方 IR                  |
| 2    | 高质量二手来源         | 0.8      | Reuters, Bloomberg, Binance, CoinGecko, DefiLlama |
| 3    | 叙事 / 传言 / AI 生成  | 0.3      | 社交媒体、匿名研报、未核验帖子                    |

## 3. 新鲜度纪律

| Freshness | 时间尺度 | 默认处理                       |
| --------- | -------- | ------------------------------ |
| `live`    | 24h 内   | 可直接进入主判断               |
| `recent`  | 2–30 天  | 可用，但需说明时滞             |
| `stale`   | >30 天   | 只可作为背景，不可作为主要触发 |

对于宏观制度类事项，可适度延长新鲜度窗口，但必须注明“慢变量”。

## 4. 结论置信度

### `high`

适用条件：

- 核心结论至少有 2 个 Tier 1/2 支撑
- 不存在强冲突证据
- 传导链条较短

### `medium`

适用条件：

- 事实基本可靠，但市场传导链条含推断
- 或存在一定冲突，需要保留条件语气

### `low`

适用条件：

- 关键支撑主要来自 Tier 3
- 或事实本身稀缺 / 矛盾 / 早期

## 5. 冲突证据处理

若存在互相冲突的证据，按以下顺序处理：

1. 先比较来源 tier
2. 再比较时间新鲜度
3. 再比较是否为直接观测而非评论
4. 若仍无法消解，降一级置信度并显式写入 `unknowns`

## 6. 未知项政策

未知项不是缺陷，而是纪律的一部分。默认至少列出：

- 当前无法确认的关键变量
- 若该变量朝相反方向发展，会如何改写结论
- 下一次应复核什么数据

## 7. 反方观点政策

每份正式结论必须包含一个“最强反方观点”：

- 不允许用稻草人反方
- 反方必须足够强，足以改变仓位
- 若反方成立，应给出新的组合姿态

## 8. 推荐表达

| 置信度   | 推荐表达                                 |
| -------- | ---------------------------------------- |
| `high`   | “大部分高质量证据支持……”                 |
| `medium` | “现阶段更合理的判断是……”                 |
| `low`    | “这更像一个待验证假说，而非可定案结论。” |

## 9. 禁止事项

- 禁止把 Tier 3 直接写成核心事实
- 禁止隐藏冲突证据
- 禁止为了形成强判断而省略未知项
- 禁止用情绪化语言替代置信度表达
